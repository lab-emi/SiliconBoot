# Simulation, coverage and verification tools

Apply the [common recipe](../README.md), [validation policy](../../docs/validation.md) and official sources in the [catalog](../../catalog/README.md). This recipe is experimental and establishes no native platform claim.

## Resolve and install

Select each simulator's current official version and host-native build route. Record language support, foreign-function interfaces, waveform formats and optional features. Python verification libraries belong in isolated environments, with simulator/VPI/VHPI compatibility resolved before building their native extensions. A waveform viewer requires data generated by a recorded simulator.

| Component | Dependency or installation concern | Required functional check |
| --- | --- | --- |
| Icarus Verilog | Compiler plus simulation runtime and support data | Compile and execute a documented self-checking example, inspect assertions and waveform output |
| Verilator | C++ toolchain, selected timing/trace features | Build and run an official example through its generated simulation model; verify expected outputs and trace data |
| GHDL | Chosen code-generation backend and toolchain | Analyze, elaborate and run a VHDL example with meaningful assertions |
| NVC | Native backend and VHDL runtime support | Analyze and run a documented VHDL example, checking expected assertions and waveform data |
| IRSIM | Technology/parameter data and input format | Simulate an upstream switch-level example with its parameter file and compare expected node transitions |
| cocotb | Simulator, interpreter, bridge ABI and supported runner | Run the upstream smallest supported regression; parse test counts and failures |
| cocotbext-ams | cocotb, analog/digital backends, integration scope | Run a documented mixed-signal example with all named backends; inspect analog values and digital assertions |
| pyuvm | cocotb and the chosen simulator | Run an official testbench example and inspect test completion and scoreboard results |
| Covered | Supported Verilog subset and simulation data format | Analyze a known example waveform and check covered and uncovered items in the coverage report |
| GTKWave | Native GUI and supported trace readers | Open the recorded waveform, locate expected signals and check timestamps and value transitions |
| Surfer | Native desktop build or another explicitly selected upstream frontend | Open the same supported waveform and confirm signal decoding and timing display |

Derive check inputs and expected outcomes from the selected upstream revision. Include a known failing test when validating a test runner so a swallowed simulator failure cannot be mistaken for success. Do not count an empty regression as passed.

## Handoff and cleanup

Record compiler/runtime entrypoints separately, especially where simulation requires a second executable. Keep VPI/VHPI modules, simulator runtime data, waveform readers, Python package contents and licenses. A headless host may verify waveform generation without verifying the GUI viewer; report those outcomes independently. Clean temporary build residue only after rerunning the example in a fresh session outside the build tree.
