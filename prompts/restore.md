# Restore an exact environment

> Find the local SiliconBoot clone and the existing project directory from context, defaulting to the clone. Restore its environment from .siliconboot/environment.lock.md, or the selected existing portable lock, using docs/upgrade.md. Read AGENTS.md and any existing .siliconboot/AGENTS.md. Reuse the recorded tool and PDK roots; on a new host use ~/tools for tools, SRAM compilers, uv and runtimes, ~/pdks for PDKs and ~/bin for public binary symlinks, without sudo or workspace creation. Preserve existing files and report any migration needed for an older environment. Resolve the lock's exact provider identities, source revisions, dependency versions, build options and patch records. Check host compatibility and artifact availability; do not replace missing inputs with latest versions. Rebuild into persistent locations, create new local records and links, and validate the recorded workflows before activation. On first setup detect the default login shell and configure ~/bin in PATH through its bashrc, zshrc or fish configuration. Report every missing, unavailable or host-dependent input and any difference from the lock. Keep the current working generation active when exact restoration or required validation is blocked.

The portable lock identifies inputs. It does not make machine-specific binaries portable or guarantee bit-for-bit rebuilds.
