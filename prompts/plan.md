# Inspect and plan

> Find the local SiliconBoot clone and plan setup using the existing project directory from context, or the clone itself. Follow AGENTS.md and docs/bootstrap.md. Plan managed EDA tools, SRAM compilers, uv and isolated runtimes under `~/tools`, PDKs under `~/pdks`, and verified public binary symlinks under `~/bin`, without sudo or workspace creation. On macOS, always check current Homebrew formulae/casks first for every tool, including uv, against the latest official upstream release, native architecture and required capabilities. Use live official metadata without installing Homebrew or changing local state. Select a matching usable Homebrew package at its recorded external locations as an exception to `~/tools`; otherwise record why and select the same latest version through an official native binary, upstream-documented installer or source build. Include exact package inputs, dependencies and generation-retention limits under docs/installation.md. Produce a proposed native installation plan without installing components, editing shell configuration, changing system packages or activating a generation. Inspect host architecture, resources, existing installations, directory ownership and binary-name conflicts. Detect the default login shell and identify its effective bashrc, zshrc or fish configuration for a future idempotent PATH update. Plan to use uv for Python environments; check whether it exists and include its installation through the selected provider before Python setup if missing. Resolve official latest versions, dependencies, coupled groups and native providers. Show all requested items, including unknown versions, unsupported or unresolved sources and privileged dependency blockers. Identify expected validation workflows and any limitations of the latest combination. Save the proposed plan inside the existing project's `.siliconboot/` only if a safe, nonconflicting record location exists; otherwise present it in the response.

A reviewed plan freezes source selections for its operation. It is not proof that the selections build or work together.

See [the macOS provider policy](../docs/installation.md#macos-check-homebrew-first) for Homebrew comparison and fallback requirements.
