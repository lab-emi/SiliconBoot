> Find the local SiliconBoot clone and plan setup using the existing project directory from context, or the clone itself. Follow AGENTS.md and docs/bootstrap.md. Plan EDA tools, SRAM compilers, uv and isolated runtimes under `~/tools`, PDKs under `~/pdks`, and verified public binary symlinks under `~/bin`, without sudo or workspace creation. Produce a proposed native installation plan without installing components, editing shell configuration, changing system packages or activating a generation. Inspect host architecture, resources, existing installations, directory ownership and binary-name conflicts. Detect the default login shell and identify its effective bashrc, zshrc or fish configuration for a future idempotent PATH update. Plan to use uv for Python environments; check whether it exists and include its official installation before Python setup if missing. Resolve official latest versions, dependencies, coupled groups and native providers. Show all requested items, including unknown versions, unsupported or unresolved sources and privileged dependency blockers. Identify expected validation workflows and any limitations of the latest combination. Save the proposed plan inside the existing project's `.siliconboot/` only if a safe, nonconflicting record location exists; otherwise present it in the response.

A reviewed plan freezes source selections for its operation. It is not proof that the selections build or work together.
