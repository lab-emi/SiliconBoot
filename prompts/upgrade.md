# Upgrade selected components

> Find the local SiliconBoot clone and the existing project directory from context, defaulting to the clone. Upgrade `<COMPONENTS_OR_PROFILE>` to the latest official versions. Read AGENTS.md, .siliconboot/AGENTS.md, docs/upgrade.md and the current receipts, catalog and recipes. Reuse the recorded tool and PDK roots, normally ~/tools and ~/pdks, without sudo or workspace creation; report any root migration needed for an older environment. On macOS, always check current Homebrew formulae/casks first against each selected tool's latest official release, native architecture and required features. Use a matching usable Homebrew package at recorded external paths as an exception to ~/tools; otherwise record why and install the same latest version through the best upstream-supported native binary, documented installer or source build. Follow docs/installation.md for Homebrew availability, dependency impact and protection of retained generations and leases. Prevent automatic cleanup and unrelated dependent upgrades; limit changes to the frozen scope and required dependencies. Query official releases or documented maintenance branches, record exact sources, and freeze a new resolution. Include affected plugins, tool ABIs, PDK model builds and memory technology dependencies. Build or install new persistent versions and validate the components and affected workflows. Keep the current generation active until the candidate passes those checks. If the latest versions are incompatible, report blocked_latest_incompatible and retain the working environment. Record any explicitly requested compatible environment separately. Activate a complete candidate atomically under the documented locks, reconcile owned ~/bin links while preserving unrelated entries, retain the previous generation, and clean up only owned temporary files.

If source discovery is unavailable, report `latest_unknown`. System package changes have separate rollback limits; see [upgrade and recovery](../docs/upgrade.md).

See [the macOS provider policy](../docs/installation.md#macos-check-homebrew-first) for comparison and retention requirements. Ordinary runs and exact restores keep their recorded providers and versions.
